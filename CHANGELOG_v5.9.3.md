# MGC Languages v5.9.3 — Multi-user LAN Readiness

## Goal

Make the service deployable on one office/server machine and reachable by multiple users from other computers on the same trusted network.

## Changes

- Added `docker-compose.lan.yml` with PostgreSQL + internal app network + nginx edge.
- Added `.env.lan.example`.
- Added `start-lan.cmd` and `scripts/start_lan_windows.ps1` for Windows one-click startup.
- LAN launcher detects the server IPv4 address, generates local secrets and writes explicit trusted hosts.
- Added `stop-lan.cmd`; PostgreSQL data volume is preserved on normal stop.
- Fixed `scripts/entrypoint.sh` to run modular `asgi:app` instead of legacy `app:app`.
- Added configurable `WEB_CONCURRENCY` with a fail-closed 1..16 range.
- Added `scripts/multi_user_smoke.py` for concurrent edge requests and latency reporting.
- Added `tests/v593_multi_user_deployment_test.py` and release shard `v593`.
- Added focused CI profile that starts PostgreSQL + app + nginx and executes 200 concurrent edge requests.
- Added `docs/MULTI_USER_LAN_v5.9.3.md`.

## Deployment semantics

- Local `docker-compose.yml` remains a SQLite developer profile.
- Multi-user LAN mode always uses PostgreSQL.
- Only nginx publishes a host port; app and database stay on the Docker backend network.
- LAN default publishes nginx on `0.0.0.0:8080`.
- `MGC_TRUSTED_HOSTS` is explicit when generated by the Windows launcher.
- Self-registration is enabled for the controlled LAN sandbox so each colleague gets an individual account.
- Corporate rollout should switch to TLS, OIDC, disabled self-registration and explicit trusted DNS hosts.

## Compatibility

- No DB schema change; Alembic head remains `c57d0a31f570`.
- No runtime `APP_VERSION` bump.
- No learning, XP, SRS, terminology, UI or language-content changes.
- Putonghua (普通话) remains the primary Chinese learning standard.

## Capacity statement

v5.9.3 removes the single-PC deployment blockers and adds concurrent-process support. It does **not** claim a fixed maximum user count. Capacity must be measured on the target server with the provided concurrent smoke/load tooling and then sized across CPU, RAM, PostgreSQL pools and TTS concurrency.
