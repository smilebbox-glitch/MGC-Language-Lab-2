# MGC Language Lab — One-click pilot start v6.0.17

## Windows operator path

Start the pilot by double-clicking:

`START_COMPANY_PILOT.bat`

The launcher first attempts a fast-forward update from GitHub `main` when Git is available, then selects the correct launch mode automatically.

## Mode A — strict corporate pilot

When real `OIDC_CLIENT_ID` and `OIDC_CLIENT_SECRET` values have been issued by the company identity provider, the launcher:

1. checks Docker Desktop / Docker Engine and Docker Compose v2;
2. generates only deployment-local secrets when they are still placeholders: `POSTGRES_PASSWORD`, `OIDC_STATE_SECRET` and `METRICS_TOKEN`;
3. validates `.env.pilot` with the strict corporate GO/NO-GO preflight;
4. keeps `AUTH_MODE=oidc`, secure cookies, RLS and content-approval requirements enabled;
5. builds and starts the PostgreSQL / app / Nginx / backup / maintenance stack;
6. waits for `/health/ready`;
7. performs runtime validation;
8. opens the pilot in the browser.

Corporate OIDC client credentials are never fabricated or generated by the launcher. They must come from IT / the corporate identity provider.

## Mode B — local/LAN pilot before SSO is available

If `OIDC_CLIENT_ID` or `OIDC_CLIENT_SECRET` is missing or still contains a template placeholder, the launcher does **not** weaken or bypass the strict corporate gate. Instead it explicitly switches to the existing local/LAN pilot launcher.

The local/LAN launcher:

- uses local authentication rather than corporate OIDC;
- generates a cryptographically random PostgreSQL password, OIDC state secret and metrics token;
- creates the local admin credential on first use;
- starts the service for this PC and, when the network permits, other PCs on the same trusted LAN;
- prints the local/LAN address after startup.

The console labels this path `[LOCAL PILOT]`. It is intended for pilot/demo and functional validation. It is **not** the corporate SSO-certified rollout profile.

Once IT supplies real OIDC client credentials in `.env.pilot`, the same `START_COMPANY_PILOT.bat` automatically returns to strict corporate mode on the next launch.

## First run

If `.env.pilot` does not yet exist, the launcher creates it from `.env.company-pilot.example`. No manual editing is required merely to run the local/LAN pilot.

For strict corporate mode, IT must still provide the real OIDC client ID/secret and valid corporate identity-provider/DNS configuration. The remaining deployment-local secrets are generated automatically.

After configuration, subsequent starts remain one double-click.

## Safety

The launcher never uses `docker compose down -v` and therefore does not intentionally delete the PostgreSQL volume. A failed strict preflight or failed readiness check stops with `NO-GO` and leaves an explicit diagnostic message.

Do not weaken OIDC, secure-cookie, RLS or content-approval readiness requirements for a real corporate rollout. The local/LAN fallback is a separate pilot mode rather than a bypass of those controls.
