# MGC Languages — план теста v5.9.7

## Цель

Провести короткий офисный multi-user тест: несколько сотрудников открывают одну LAN-ссылку с разных компьютеров, создают отдельные аккаунты и работают со своим прогрессом.

## Первый запуск на Windows-сервере

1. Запустить `start-lan.cmd` двойным кликом.
2. При первом запуске launcher попросит пароль для `admin`.
3. Ввести заранее согласованный тестовый пароль администратора. Пароль сохраняется только локально в `.env.lan`, который исключён из Git.
4. Дождаться `Readiness: OK`.
5. Скопировать показанную ссылку вида `http://192.168.x.x:8080` и отправить участникам теста.

Если `.env.lan` уже существует, launcher не меняет пароль без явного параметра `-AdminPassword`; при старте приложение синхронизирует DB admin с текущим значением `MGC_ADMIN_PASSWORD` из `.env.lan`.

## Сотрудник

При регистрации сотрудник вводит:

- имя и фамилию;
- уникальный логин;
- отдел;
- пароль.

Доступные отделы в тестовом UI: R&D, Производство, Сборка, Сварка, Окраска, Штамповка, Компоненты, Качество, Логистика, Закупки, Финансы, IT, HR, Администрация и Другое.

При последующем входе браузер просит:

- логин;
- отдел;
- пароль.

Для обычного пользователя переданный отдел сверяется с сохранённым профилем. Это помогает избежать случайного входа под чужой учётной записью.

## Администратор

- login: `admin`;
- department: `Администрация` (UI выбирает его автоматически после ввода login `admin`);
- password: задаётся локально при первом LAN-запуске и не хранится в репозитории.

Администратор должен видеть `Admin / Analytics`, пользователей и их подразделения.

## Быстрый сценарий теста

1. Открыть сервис минимум на 3 разных компьютерах.
2. Зарегистрировать 3 разных аккаунта из разных отделов.
3. На каждом аккаунте пройти один quiz / practice.
4. Перезайти и проверить, что прогресс каждого пользователя сохранился отдельно.
5. Попробовать войти с правильным логином/паролем, но неправильным отделом — сервис должен отказать.
6. Войти как admin и проверить список пользователей/отделов.
7. При возможности запустить `python scripts/multi_user_smoke.py --profile office` и сохранить показатели latency/success rate.

## После теста

Для корпоративного rollout рекомендуется перейти с local registration на OIDC/SSO, отключить открытую саморегистрацию, включить TLS и использовать корпоративное DNS-имя вместо IP.
